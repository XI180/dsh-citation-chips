# dsh-citation-chips

给 [DeepSeek Harness](https://github.com/deepseek-ai) 的「引用角标」bundle。

它让模型在**每一句引用了检索材料的话末尾**，紧跟一个「本身就是链接」的数字角标 `[1](https://…)`，并在回答结尾附一份 `来源` 清单。角标可点击，不会变成一排光秃秃的 `[1] [2] [3]` 却不知道对应哪条来源。

> Host-only：不渲染界面，只注入一条系统提示词规则。约 700 字符，随每次请求下发。

## 效果

没有它的时候：

```text
根据官方价目，MiniMax H3 768P 是 ¥0.50/秒。另外 2K 是 ¥0.80/秒。
```

装上之后：

```text
根据官方价目，MiniMax H3 768P 是 ¥0.50/秒，15 秒约 ¥7.5[1](https://platform.minimax.cn/docs/pricing/overview)。2K 档是 ¥0.80/秒[1](https://platform.minimax.cn/docs/pricing/overview)。

来源
1. [MiniMax 开放平台 · 定价概览](https://platform.minimax.cn/docs/pricing/overview)
```

同一条来源复用同一个编号；结尾清单按首次出现顺序编号，默认最多 9 条。

## 它做什么

在系统提示词里插入一个 section（`order: 2250`，紧跟 `TOOL_WEB_SEARCH: 2000`、`TOOL_WEB_FETCH: 2100` 之后），规定五条：

| 规则    | 说明                                          |
| ----- | ------------------------------------------- |
| 角标即链接 | `[1](https://example.com/page)`，不是纯文本 `[1]` |
| 位置    | 挂在其支撑的那句话末尾、句号之前                            |
| 编号    | 从 1 起，按首次出现顺序，同一来源复用同一编号                    |
| 不编造   | 只能指向本轮真正检索到的 URL                            |
| 收尾    | `来源` 清单，`n. [标题](url)`，超过上限截断               |
| 兜底    | 没有任何检索来源时，一个角标都不写，也不写清单                     |

## 它不做什么

- **不画 chip**。不改变链接的视觉样式，链接就是普通行内链接（点击后按「设置 → 通用设置 → 网页链接默认打开方式」打开）。
- **不抓数据**。不做检索、不做缓存、不改工具输出。
- **不硬校验**。提示词是软约束，模型仍可能漏标或编号错位（见「已知限制」）。

## 配置

`cordis.patch.yml` 里的 `config.maxSources` 控制 `来源` 清单条数上限：

```yaml
- insert:
    - id: citation-chips
      name: dsh-citation-chips
      config:
        maxSources: 9
```

- 默认 `9`，最大 `30`；
- 非数字、`0`、负数都会回落到默认值；
- 改完重载插件即可，无需重启进程。

## 限制

- **软约束**：提示词不能强制模型。引用密集的答案里仍可能出现编号重复、跳号、或某句该标未标。
- **不是 chip**：视觉上就是普通链接。
- **依赖宿主的链接行为**：角标可点击，但打开方式由 Harness 的设置决定。
- **只影响新对话**：已生成的历史消息不会回溯补标。

##

## 兼容性

- 需要一个暴露 `systemPrompt` 服务的 Harness 版本（Host 侧），与是否启用 Web 前端无关；
- 纯 ESM，无生产依赖；
- 与任何 UI 皮肤、主题插件互不冲突（它不碰 DOM）。
